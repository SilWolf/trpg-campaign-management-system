# v0.1.0 — 多戰役跑團管理平台

v0.1.0 整理目前已實作的網站功能，提供 D&D 5R（2024）戰役使用的角色背包、物品工坊、商店與冒險紀錄管理。

## 戰役、帳號與角色

- 支援登入、註冊、Email 邀請加入戰役，以及個人資料管理。
- 戰役大廳可建立戰役、透過邀請碼加入戰役，並管理各成員的角色數量上限。
- 戰役設定包含一般設定、成員配額及各角色的獨立權限設定。
- 角色資料支援名稱、頭銜、力量值與頭像；符合權限的成員可編輯角色。
- 角色權限以每個戰役、每個角色分別管理。DM 保有管理權；玩家依角色 ACL 取得閱讀或修改權限，並透過即時同步更新畫面。

## 角色背包、錢包與營地儲物箱

- 背包支援格狀、緊湊格字及列表檢視，物品可按類別整理，並呈現武器／護甲屬性、稀有度、附魔詞條、充能、Markdown 說明與裝備狀態。
- 未鑑定物品可隱藏玩家不可見的定義與 DM 備註；物品、公開背包及私人暗袋依 ACL 控制。
- 角色具有公開與私人錢包，支援 PP、GP、EP、SP、CP、換算及負重顯示。負重只計入使用者有權閱讀的資料。
- `camp-chest` 是虛擬儲存庫，不會建立虛擬角色資料列。營地箱物品仍以目前戰役隔離；營地箱貨幣由戰役資料保存，而不是寫入虛擬角色錢包。
- 具備來源修改權的玩家可將物品或貨幣移轉給其他角色或營地箱；跨角色／戰役貨幣資料列的前端移轉目前不是單一資料庫交易，不保證原子性。
- DM 可依角色權限管理背包與錢包存取；刪除角色時，依既有流程將遺物及錢包併入營地儲物箱。

## 鍛造工坊與戰役商店

- 鍛造工坊提供官方規則書物品目錄的瀏覽、搜尋、篩選與詳情檢視，也提供個人自創物品的建立、保存及分享。
- DM 可將目錄或分享物品匯入戰役角色或營地箱；匯入後成為獨立的戰役物品，不依賴來源樣板繼續存在。
- 每個戰役可有多家 DM 管理的商店。DM 可管理商店、商品、價格、庫存及審查設定，亦可設定刷新政策並預覽刷新結果。
- 玩家可選擇自己的角色與具有修改權的錢包購買；支援待審請求、DM 核准／拒絕、購物紀錄及庫存管理。結帳及刷新透過資料庫交易流程處理。

## 冒險筆記與圖片

- 戰役成員可建立、篩選及檢視冒險筆記，記錄 Markdown 內容、標籤、任務與完成狀態。
- 筆記可設為公開或綁定角色的私人筆記；DM 另有僅 DM 可讀寫的筆記內容。筆記權限由角色 ACL 與資料庫政策共同限制。
- 角色頭像、鍛造工坊物品、戰役物品與冒險筆記支援圖片參照及上傳；預設物品圖片由網站靜態資產提供。
- 使用者上傳圖片儲存於 Supabase Storage，圖片採公開讀取網址；請勿上傳包含暗袋、DM 筆記或其他敏感資訊的圖片。

## 介面與操作體驗

- 延續《博德之門 3》風格的暗黑奇幻介面，提供 `default`、`dnd` 與 `printing` 三種主題，稀有度色彩亦隨主題調整。
- 提供共用表單與互動元件、全域操作提示，以及重要或破壞性操作的確認對話框。
- 訪客、離線或未設定 Supabase 的情境提供本機狀態退避；退避模式不會假稱資料已同步至雲端。

## 資料同步與部署注意事項

- 遠端戰役資料依 `campaign_id` 隔離，透過 Supabase Auth、PostgreSQL RLS、受限 RPC、Edge Functions 與 Realtime 支援網站功能。
- 本版將原有 Supabase SQL migrations 依時間順序整合為單一檔案：[20261030000012_v0_1_0.sql](../../supabase/migrations/20261030000012_v0_1_0.sql)。檔案中的來源標記保留原始 migration 名稱與執行順序。
- 整合檔包含「既有 schema 基線」檢查，要求目標資料庫已保留本專案的核心資料表；它不是可直接建立全新空資料庫的完整 schema 初始化檔。
- 原 migration 曾被個別套用的 Supabase 環境仍保有舊 migration history。本次沒有連線、執行 SQL、部署 Edge Function 或修改 Secrets；維護者需先核對目標專案、備份與遠端 history，並在隔離環境規劃 history 對齊及驗收。未完成前不可直接推送整合 migration，也不可宣稱資料庫已按本版驗收。
- Playwright 的 Supabase Auth、REST、RPC 與 Edge Function 測試使用替身；本機測試結果不代表真實資料庫、RLS、Realtime、Storage 或交易回滾已驗收。
